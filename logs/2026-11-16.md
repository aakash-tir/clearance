# 2026-11-16

## Feasibility check and repositioning as a portfolio project

**What we did:** Reviewed the original brief (now `docs/history/plan-original.md`): a
self-hosted, model-agnostic company assistant where each employee only sees data their
role allows. Decided to build it as a portfolio and learning project, replacing nova-lite.

**The reason:** The market is crowded. Microsoft 365 Copilot, Glean, Gemini Enterprise
and Amazon Q (now closed to new customers) cover the cloud side, and Onyx covers
self-hosted, but keeps permission sync in its paid Enterprise licence. Mid-size companies
would pick Copilot; the self-hosted buyers (regulated, air-gapped) are few and slow to
sell to, and the owner has no industry connection to target a niche. As a portfolio piece,
though, permission-aware retrieval + identity sync + leak testing is exactly the hard,
in-demand part. Details: `docs/research/01-market-and-competitors.md`.

**How it was solved:** Added a "learning mode" to the plan: one concept per PR, every
file, test and correction explained, plain-language concept notes in `docs/learning/`.

## Expanded the plan and chose the stack

**What we did:** Researched leak mechanisms, vector stores, model servers, models for a
12 GB GPU and Entra ID group sync, then asked the owner four questions. Rewrote
`plan.md` with scope, stack table, architecture, the hard part, testing strategy and
milestones M0–M7.

**The reason:** Owner choices (all the recommended options):
- **Postgres + pgvector** over Qdrant: the ACL filter sits in the same SQL as the vector
  search, and row-level security gives a second, database-enforced lock. Qdrant would
  mean a second service and ACLs copied into payloads with no DB-level lock.
- **Entra ID from day one** over a Keycloak stand-in: matches the brief ("use the Azure
  hierarchy"). Needs a free Azure tenant, because the M365 Developer sandbox is hard to
  qualify for in 2026.
- **Fake company folder first** over SharePoint straight away: known content allows exact
  no-leak assertions. SharePoint moves to the backlog.
- **Small React UI** over API-only: demoable.

Fine-tuning was rejected outright: weights can't carry access control, and swapping the
model would mean retraining (`docs/research/02-why-permission-aware-rag.md`).

**How it was solved:** Research files with sources in `docs/research/`; the decision table
in `plan.md`; deferred items in `docs/future.md`.

## Scaffolded the project, tests and CI

**What we did:** Ran the init-project layout (`.claude/` rules, protect-main hook,
graphify in shared mode without git hooks, architecture-diagram skill). Added a FastAPI
skeleton (`/health`, typed settings) and a React shell, each with real tests, plus
PR-only, path-filtered CI (`backend.yml`, `frontend.yml`), PR and issue templates, and the
learning-mode rule (`.claude/rules/learning-mode.md`).

**The reason:** The repo must be runnable and testable before any feature work, and the
owner's "explain everything" requirement has to be a rule that every session loads, not
a one-off request.

**How it was solved / corrections along the way:**
- **mypy "unused type: ignore"**: the tests had `# type: ignore[call-arg]` on
  `Settings(_env_file=None)`. With the pydantic mypy plugin, mypy already understands
  `_env_file`, so the ignores were flagged as unused under `strict`. Removed them.
- **Starlette deprecation warning**: `Using httpx with starlette.testclient is deprecated;
  install httpx2 instead.` Swapped the dev dependency from `httpx` to `httpx2`, which also
  matches the owner's standard. Warning gone.
- **Vitest 5 wouldn't install**: `npm error Cannot read properties of null (reading
  'edgesOut')` from npm 10.8.2 / Node 20.19.5, even after a clean reinstall. Vitest 4.1.12
  also supports Vite 8 (`peerDependencies.vite: ^6 || ^7 || ^8`) and installed cleanly, so
  it's pinned to `^4.1`. Revisit on a newer npm.
- **Template tooling**: the current Vite template ships oxlint, not ESLint; kept oxlint and
  updated the plan's stack table.
- **Tests can fail**: checked by breaking the code on purpose. Renaming the heading failed a
  frontend test, and changing `/health`'s status failed a backend test. Both restored.

No architecture diagram yet: the skeleton has no real architecture to draw. It will be
created by the first M1 PR that adds the database.
